🔗 五大 Agent 串接圖 —— 中間兩格怎麼接起來

AI 決策 Agent（揀料出貨）與 AI 服務 Agent（安裝驗收）的下游流程接線規格

先講結論

要接的 11 條線裡，有 8 條不需要等 ERP。
現在就能把「服務流」整段串起來。
五大 Agent 本來就是一條鏈：客服受理 → 會員建單 → 決策揀料出貨 → 服務派工安裝 → 保固再購。 中間兩格沒接下游，等於「從訂單到交付」這一段是斷的——這正是現況圖痛點 3 說的「前台互動與 ERP 交易斷鏈」。
真正卡 ERP 的只有訂單流那幾條（庫存、交期、出貨確認）；服務流（派工、回報、驗收、保固起算、代收核銷）完全不碰 ERP，可以先接。

串接後的資料流

橘色虛線＝本次要接的線（不需 ERP）　灰色虛線＝需要 ERP 或外部帳號　實線＝原本就有
原有 要接・可立即做 要接・卡 ERP／外部帳號

⚠️ 第 4 條「出貨確認」是唯一擋住服務流的那道閘門——但它有過渡解法

安裝派工必須先確認貨已出（不然師傅到現場沒東西可裝）。這個確認資料在 ERP 裡，而 ERP 本期不串。 表面上看，這會讓整條服務流卡住。

但我方 MVP 現在就是這樣做的：安裝單有一道「ERP 出貨閘門」——助理手動填入 TIPTOP 出貨單號與日期後， 排程派工才解鎖。先照這個做法，人工填單號當橋接，服務流就能立刻整段串起來；等 ERP 串好，同一個欄位改成自動寫入即可， 流程不用重做。這是「不等 ERP 也能上線」的關鍵。

🗓️ 建議接線順序

先接：服務流（6→7→8→9→11）

完全不碰 ERP、不需外部帳號。接完就是一條可運作的「報修→派工→回報→驗收→保固」閉環，也直接解掉中區與北區訪談的主要痛點。
  • ⑥ 報修自動開單
  • ⑦ 帶入客戶與保固資訊
  • ⑧ 派工含費用／師傅回報
  • ⑨ 驗收 → 保固起算
  • ⑪ 逾時警示廣播

再接：金流與訂單前段（10→1→3）

代收核銷不依賴 ERP，可跟服務流一起做。訂單觸發揀料只需要 Agent 之間傳訊，也不必等 ERP。
  • ⑩ 代收保管 → 繳回核銷
  • ① 訂單成立 → 觸發揀料
  • ③ 缺料 → 供應商

最後：ERP 與外部帳號（2→4→5）

依賴外部系統與帳號體系。第 4 條可先用人工填出貨單號橋接，不阻擋前面兩批。
  • ② ERP 庫存交期唯讀
  • ④ 出貨確認自動化
  • ⑤ 鎖店回報備品（需帳號）
📌 畫這張圖時要一起改的三件事
項目說明
兩格改成「建置中」不是灰 灰色在圖例裡對應「非本計畫」，容易被誤讀成排除在外。建議改為虛線外框＋「本期串接」標記，語意才對得上。
保固起算不是單一基準 第 ⑨ 條要傳的是「保固起算基準」而非固定日期——零售用登錄日、經銷用出貨日、合約案用使照日、分批出貨用大貨日。北區訪談已否定「統一登錄制」。
140 位師傅要落成名冊 第 ⑤、⑧ 條都以師傅端為節點，但中區訪談指出公司層級無完整外包師傅名冊。名冊不建，這兩條接不上；建了則同時是補助案「帶動中小微企業導入」的現成名單。
