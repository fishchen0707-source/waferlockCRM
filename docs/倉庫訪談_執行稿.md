# 倉庫訪談執行稿

> 搭配 [`倉庫訪談清單.md`](倉庫訪談清單.md) 使用。
> 那份是「為什麼要問」（按會不會推翻程式排序），這份是「現場照著走」。
> 預計 60～90 分鐘。**順序刻意不是技術優先序**——先讓他們講，最後才問我們想確認的。

---

## ⚡ 如果只有 20 分鐘，只問這五題

1. **上次漏配件是什麼時候？漏了什麼？怎麼發現的？**（→ 出貨檢驗要不要逐項打勾）
2. **回報「有問題」之後，那張單接下來怎麼走？**（→ 會直接推翻現有程式）
3. **產品序號記在哪？誰會回頭查？**（→ 保固追溯的斷點）
4. **託運單號是誰產生的？抄在哪？**（→ 解掉託運單配對的老問題）
5. **公司的 ISO 文件管制清單可以給我一份嗎？**（→ 拿到完整流程地圖，不必再猜）

第 5 題不是問倉庫，是問管理代表或品保 —— 但當場提起最不會忘。

---

## 第一段（15 分鐘）：先閉嘴，讓他們講

**不要**一開始就問我們想問的。先問這一題，然後盡量不打斷：

> 「可以請你從早上進來到下班，講一遍你一天大概在做什麼嗎？」

聽的時候記三件事：
- 他提到的**每一個系統或紙本**（Teams、LINE、TipTop、手寫本、白板、Excel）
- 他**等別人**的時間點（等業務補資料、等助理開單、等貨到）
- 他**重複做兩次**的動作（抄一次又打一次）

接著只問一句：

> 「這裡面哪一段最花時間？」

⚠ **這一題的答案可能推翻我們整個方向。** 如果他說「最花時間是等業務把資料補齊」，那瓶頸根本不在倉庫，我們做的倉庫核單頁價值有限。

---

## 第二段（20 分鐘）：從最近的實例挖，不要問假設

問「上週／最近一次」，不要問「會不會」「有沒有可能」。

| 問法 | 想知道的 |
|---|---|
| 「最近一次撿不出料是什麼時候？那次怎麼處理的？」 | 缺料頻率、當下的處理路徑 |
| 「上次漏配件／裝錯規格是什麼時候？」 | **出貨檢驗要不要逐項打勾** |
| 「有沒有遇過業務給的資料看不懂或不完整？」 | 上游資料品質 |
| 「有沒有寄錯地址或寄錯人的經驗？」 | 貨指寄／客人地址混淆的實際風險 |
| 「最近一次客戶說少東西是什麼情況？」 | 客訴回頭找得到證據嗎 |

**追問公式**：聽到任何問題，都追這三句 ——
「那次怎麼發現的？」「後來怎麼解決？」「有沒有留下記錄？」

第三句最重要：**沒有記錄的問題會一直重複發生**，而那就是系統該補的地方。

---

## 第三段（15 分鐘）：讓他們動手，你在旁邊看

拿手機打開倉庫核單頁，請他實際核一筆（副本上，不影響正式資料）。

**你只說一句：「你試著把這筆處理掉。」然後不要教、不要提示。**

觀察並記錄：
- 他第一眼先看哪裡？（如果先找品項而不是單號，卡片的資訊順序就該調整）
- 有沒有停頓、皺眉、反覆滑動？
- 「有問題」那顆按鈕他敢不敢按？**如果他猶豫，代表他不確定按了會發生什麼事**
- 字夠大嗎？站著單手拿得住嗎？

⚠ 這一段是唯一能得到「他實際怎麼用」的機會，比任何口頭回答可靠。**不要為了趕時間跳過。**

問完再問一句：

> 「如果這個要取代你現在的做法，缺什麼？」

---

## 第四段（25 分鐘）：確認題

前面沒自然浮現的才問。**每題都記答案，不要只記「有／沒有」。**

### 撿料與核單

- [ ] 撿料時遇到的狀況有哪幾種？（缺料／料號不符／數量不對／包裝破損／其他）
- [ ] 每一種各自怎麼處理？誰要來解決？
- [ ] **回報問題後，那張單是同一張繼續，還是重開一張？**
- [ ] 一張出貨單會不會分兩次送？多久一次？
- [ ] 出貨前有沒有檢查表／檢核動作？（本體／配件／說明書／保證書／防撞材）
- [ ] 誰負責檢？跟撿料的是同一個人嗎？

### 序號

- [ ] 序號是每台都記，還是只記起訖（連號）？
- [ ] 記在哪裡？（紙本／Excel／直接打在 Teams）
- [ ] 誰會回頭查？什麼情況下查？
- [ ] 保固登錄那邊拿得到這個序號嗎，還是各記一份？

### 貨運與託運單

- [ ] 有幾家貨運？怎麼決定用哪一家？
- [ ] 叫車是誰打電話／上系統？
- [ ] **託運單號抄在哪？**
- [ ] 同一天多張單會不會併成一張託運單？
- [ ] 「客戶寄件」是什麼情況？（客戶自己叫車？）

### 發票

- [ ] 發票是誰印、誰貼、誰寄？
- [ ] 「貼外箱」「電子檔給某人」「PDF」這幾種怎麼決定？
- [ ] 有沒有漏寄或寄錯發票的經驗？後來怎麼補？
- [ ] 退貨時發票怎麼處理？（作廢／折讓單）誰在做？

### 簽回

- [ ] 多少比例的單要簽回？
- [ ] 簽回的紙本收在哪？
- [ ] **有沒有追蹤誰還沒簽回？**
- [ ] 沒簽回會影響收款嗎？

### 場地與人

- [ ] 倉庫有幾個人？分工怎麼分？
- [ ] 會不會兩個人同時處理同一張單？
- [ ] 撿料的是專職倉管，還是師傅兼？
- [ ] 出貨地點有幾個（中科／台北／台中）？怎麼決定從哪裡出？
- [ ] 一天出貨幾次？有截單時間嗎？
- [ ] 用手機還是電腦？要不要印紙本？

### 料號

- [ ] `4121L372X001-V03` 這種品號的完整清單哪裡拿得到？TipTop 能匯出嗎？
- [ ] 光看品號知道要撿哪個規格嗎？還是要看案名裡的「68右外」？
- [ ] **組態碼（`L372-1A11A1-…`）和品號之間是誰在對？對照表在哪？**
- [ ] `L901`、`D310` 有下單規格表嗎？（規格表庫裡找不到）

### 併箱與包裝

- [ ] 併箱多常見？併箱時箱單怎麼寫？
- [ ] 「另包一箱」這種要求多不多？
- [ ] 包裝材料誰準備？會不會缺？

---

## 第五段（10 分鐘）：收尾的兩題

這兩題經常問出前面所有問題都沒問到的東西：

> 「如果可以改一件事讓你的工作變輕鬆，你會改什麼？」

> 「有沒有什麼是我沒問到、但你覺得我應該知道的？」

第二題請等他想，**不要急著填補沉默**。

---

## 訪談時的紀律

- **問實際發生的事，不要問「你覺得應該怎樣」。** 後者會得到想像的答案。
- **不要解釋系統為什麼這樣設計。** 你一解釋，他就會開始配合你的想法回答。
- **不要辯護。** 他抱怨的每一句都是資料，不是批評。
- **記原話。** 「他說很麻煩」沒有用；「他說每次都要回去問業務型號到底是哪個」才有用。
- **兩個人去**（一個問、一個記）如果做得到。

---

## 訪談後 24 小時內要做的

趁記憶還在：

1. 把答案填回 [`倉庫訪談清單.md`](倉庫訪談清單.md) 的 A／B／C／D 各題
2. 把「會推翻現有實作」的項目挑出來（那份清單最後一節有列判準）
3. 更新 [`訂單出貨總表_設計.md`](訂單出貨總表_設計.md) 的「尚未確認」那一節
4. 特別記下**他們現在有在用、但系統完全沒有的東西**——那些才是漏掉的流程

## 附：這次訪談想驗證的假設（不要念給他們聽）

自己心裡有數就好，避免問成引導式問題：

| 我們的假設 | 如果錯了會怎樣 |
|---|---|
| 倉庫是一個地方、一份名單 | 核單頁要分地點、通知要分群組 |
| 「有問題」回報後有人會重開一張單 | 單子會憑空消失，沒人知道卡在哪 |
| 一列＝一次出貨 | 分批出貨裝不下第二次核單記錄 |
| 撿錯料是主要痛點 | 如果主要痛點是「等業務補資料」，方向要改 |
| 手機優先是對的 | 如果他們印紙本，該做的是列印功能 |
| 序號只是記錄 | 如果它是保固憑證，優先度要往上拉 |
